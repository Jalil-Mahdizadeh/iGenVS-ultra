# iGenVS-ultra command-line reference

This page documents every command and option exposed by the public
`./igenvs-ultra` launcher. It is organized by task so that normal users do not
need to read one very large generated `--help` listing.

The component images also contain lower-level `igenvs`, `igen3`, and `gmolai`
commands. Their references are linked under [Component CLIs](#component-clis).

## Start here

The general form is:

```text
./igenvs-ultra COMMAND [OPTIONS]
```

| Command | Purpose |
| --- | --- |
| `doctor` | Check assets, containers, tools, and GPU visibility. |
| `dock` | Generate or read molecules and physically dock them with Uni-Dock or AutoDock-GPU. |
| `fit` | Prepare a target, dock the fixed training references, fit the target heads, and optionally run active learning. |
| `screen` | Score an external or generated library with an already fitted target. |
| `screen-fast` | Maximum-speed generated screening using only a molecule count. |
| `run` | Perform `fit` and then `screen` in one resumable job. |
| `status` | Show completed and incomplete stages of a job. |

Common examples:

```bash
# Verify the installation.
./igenvs-ultra doctor

# Physically dock the included example.
make dock

# Generate and commit exactly 10,000 finite scores with the example head.
make screen N=10000

# Inspect any fit/run job.
./igenvs-ultra status --job-dir runs/my-target
```

`auto` means that the launcher selects a value from the visible hardware,
current CPU affinity, available memory, workload, and qualified performance
profiles. `unset` means that the option is not passed and the documented model
or engine default is used. A *switch* takes no value and is off unless written.
All counts described as positive integers must be greater than zero.

## Global flags

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `-h`, `--help` | switch | off | Show help for the root command or selected subcommand and exit. |
| `--version` | switch | off | Print the iGenVS-ultra pipeline version and exit. Place it before a command. |

For the authoritative help generated by the installed version, run
`./igenvs-ultra COMMAND --help`.

## Runtime, containers, and GPUs

These options apply to `doctor`, `dock`, `fit`, `screen`, and `run`, except
that the two gMolAI image overrides do not apply to the docking-only `dock`
command.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--execution` | `auto`, `docker`, `apptainer`, `native` | `auto` | Choose the runtime. Auto prefers complete local SIFs, then the two Docker images, then native commands. |
| `--assets-dir` | directory path | repository/discovered asset root | Override the iGenVS-ultra source and release-asset root. |
| `--igenvs-image` | SIF path | `IGENVS_IMAGE` or discovered SIF | Override the iGenVS Apptainer image. |
| `--igenvs-docker-image` | image name or digest | `igenvs-ultra/igenvs:latest` | Override the iGenVS Docker image. The `IGENVS_DOCKER_IMAGE` environment variable is the fallback. |
| `--gmolai-image` | SIF path | `GMOLAI_IMAGE` or discovered SIF | Override the gMolAI Apptainer image. Used by `doctor`, `fit`, `screen`, and `run`. |
| `--gmolai-docker-image` | image name or digest | `igenvs-ultra/gmolai:latest` | Override the gMolAI Docker image. The `GMOLAI_DOCKER_IMAGE` environment variable is the fallback. |
| `--gpu-ids` | comma-separated indices or GPU UUIDs | `CUDA_VISIBLE_DEVICES`, otherwise discovered GPUs | Restrict the devices visible to the workflow, for example `--gpu-ids 0,2`. |

The launcher never requests an HPC allocation. Run it inside the interactive,
Slurm, or other allocation whose GPUs and CPUs it should use.

## Targets and job locations

The target options apply to `dock`, `fit`, and `run`. Choose exactly one target
source: `--complex`, `--receptor`, or `--prepared-target`.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--complex` | PDB path | one target source required | Use a protein and bound ligand contained in one PDB file. |
| `--receptor` | PDB path | one target source required | Use a curated/protonated receptor PDB. Requires `--reference-ligand`. |
| `--prepared-target`, `--target` | prepared-target directory | one target source required | Reuse an existing iGenVS target bundle. The two spellings are aliases. |
| `--ligand-id` | `RESNAME` or `CHAIN:RESNAME:RESSEQ` | inferred only when unambiguous | Select the bound ligand in `--complex`, for example `A:LIG:501`. Valid only with `--complex`. |
| `--reference-ligand` | single-molecule 3D SDF path | required with `--receptor` | Supply an aligned bound ligand used to define the pocket. Valid only with `--receptor`. |
| `--padding` | float >= 0, angstrom | `5.0` | Add this distance around the bound ligand when constructing the docking box. |
| `--target-name` | filename-safe text | target input stem | Override the target label recorded in outputs. |
| `--output-dir` | directory path | required | New or resumable job directory for `dock`, `fit`, or `run`. |
| `--job-dir` | directory path | required | Completed fit/run job used by `screen`, or inspected by `status`. |
| `--dry-run` | switch | off | Validate inputs and print the execution plan without running it. Available on `dock`, `fit`, `screen`, and `run`. |

The receptor and reference ligand must already use the same coordinate frame.
Re-running the same command resumes compatible completed stages; changing a
scientific setting normally requires a new job or screen name.

## Molecule-library input

`dock`, `screen`, and `run` require exactly one library source:
`--input` or `--generate-count`. In `run`, this is the final neural-screening
library; the fixed fitting libraries are supplied by the release assets.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--input` | CSV, TSV, or SMI path | one library source required | Read an existing molecular library. |
| `--generate-count` | positive integer | one library source required | Generate with iGen3. For `screen`/`run`, this is the number of successfully encoded and scored molecules to produce. |
| `--input-format` | `auto`, `csv`, `smi` | `auto` | Infer the format or select it explicitly. |
| `--smiles-column` | column name | `smiles` | CSV/TSV column containing SMILES, matched case-insensitively. |
| `--id-column` | column name | unset | Source identifier column. Stable generated row identifiers are used when omitted. |
| `--delimiter` | `auto`, one character, or literal `\t` | `auto` | Delimiter for tabular input. |

Generation-only options are ignored when `--input` is selected. Seed options
cannot be combined with external input.

## SMILES generation

These options control iGen3 when `--generate-count` is selected. The basic
options apply to `dock`, `screen`, and `run`.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--model` | `base-isomeric`, `base-nonisomeric`, `rl-isomeric`, `rl-nonisomeric` | `rl-nonisomeric` for `dock`; `base-isomeric` for `screen`/`run` | Select the bundled iGen3 checkpoint and stereochemistry policy. |
| `--generation-mode` | `de-novo`, `derivative` | `de-novo` | Generate from scratch or condition generation on seed SMILES. |
| `--seed-file` | text/SMI path | unset | Read derivative seeds, one SMILES per line. Required for derivative `dock`; for `screen`/`run`, either this or `--seed-smiles` is required. |
| `--samples-per-seed` | positive integer | `1` | Derivative samples requested per seed in each sampling cycle. |
| `--generator-batch-size` | `auto` or positive integer | `auto` | iGen3 GPU sampling batch. Auto selects and caches a safe hardware-specific value. |
| `--generator-max-batch-size` | positive integer | `32768` for `dock`; `131072` for `screen`/`run` | Safety ceiling for automatic generator batch selection. |
| `--model-dir` | directory path | bundled iGen3 models | Override the checkpoint/vocabulary root. |
| `--temperature` | float > 0 | model/mode default | Override sampling temperature. See the model-default table below. |
| `--top-k` | integer >= 0 | `64` | Sampling cutoff; `0` disables top-k filtering. |
| `--compile-generator` | switch | off | Enable the qualified `torch.compile` generation path. Compilation can cost more than it saves on short runs. |
| `--generator-seed` | integer | `13` | Base random seed for deterministic generation lanes. |

Model temperature defaults:

| Model family | De novo | Derivative |
| --- | ---: | ---: |
| `base-isomeric`, `base-nonisomeric` | `1.0` | `1.5` |
| `rl-isomeric`, `rl-nonisomeric` | `1.2` | `2.0` |

The following advanced generation options apply only to `screen` and `run`:

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--seed-smiles` | SMILES; repeatable | none | Add one inline derivative seed. Repeat the flag for multiple seeds. |
| `--greedy` | switch | off | Use argmax decoding instead of stochastic sampling. |
| `--compile-mode` | PyTorch compile-mode name | `reduce-overhead` | Mode passed to `torch.compile` when `--compile-generator` is enabled. |
| `--include-seed-molecules` | switch | off | Permit derivative output identical to a seed molecule. |
| `--max-candidates` | positive integer | unset | Hard cap on sampled candidates used to fill the requested valid-unique output. |
| `--max-candidate-multiplier` | float >= 1 | `50.0` effective | Candidate cap multiplier used when `--max-candidates` is unset. |
| `--stagnation-limit` | integer >= 0 | `max(10000, 10 x batch size)` | Stop after this many candidates produce no new valid unique molecule; `0` disables this stop. |
| `--generator-device` | `auto`, `cpu`, `cuda`, or `cuda:N` | `auto` | Override the iGen3 Torch device. Normal GPU runs should keep auto. |
| `--generator-dtype` | `auto`, `float32`, `float16`, `bfloat16` | `auto` | Override generator inference precision. Auto selects a compatible qualified type. |
| `--generator-metrics` | switch | off | Compute and retain iGen3 RDKit generation metrics for each stream batch. |

Derivative mode requires seed input. De novo mode rejects `--seed-file` and
`--seed-smiles`. `--top-k` must be non-negative and
`--max-candidate-multiplier` must be at least one.

## Docking

Docking options apply to `dock`, `fit`, and `run`. `dock` physically docks the
user library. `fit` and the fit portion of `run` dock the fixed UDRL and active-
learning libraries; the final ultra screen is neural and does not physically
dock every generated molecule.

### Engine and search protocol

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--engine` | `unidock`, `autodock-gpu` | `unidock` | Select the physical docking backend. |
| `--search-mode` | `fast`, `balance`, `detail` | `balance` for `dock`; `fast` for `fit`/`run` | Select the engine effort preset. AutoDock-GPU maps these to 10, 20, and 50 LGA runs. |
| `--scoring` | `auto`, `vina`, `vinardo`, `ad4` | `auto` | Auto chooses Vina for Uni-Dock and AD4 for AutoDock-GPU. Incompatible engine/scoring pairs are rejected. |
| `--num-modes` | positive integer | `1` | Number of poses requested per ligand. AutoDock-GPU currently supports one. |
| `--energy-range` | float | `3.0` | Uni-Dock output energy window in kcal/mol. |
| `--refine-step` | positive integer | `3` | Uni-Dock explicit-receptor refinement steps. |
| `--no-refine` | switch | off | Disable Uni-Dock explicit-receptor refinement. |
| `--unidock-verbosity` | `0`, `1`, `2` | `0` | Uni-Dock engine log verbosity. |
| `--seed` | integer | `181129` | Physical docking random seed. |
| `--max-gpu-memory` | integer >= 0, MiB | `0` | Uni-Dock GPU-memory cap; `0` keeps the engine default. |

### AutoDock-GPU controls

These are ignored by Uni-Dock unless otherwise reported as an invalid
combination.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--adgpu-runs` | positive integer | selected search preset | Override the AutoDock-GPU LGA run count. |
| `--adgpu-evaluations` | positive integer | unset/engine heuristic | Set a hard maximum score-evaluation count per LGA run. |
| `--adgpu-no-heuristics` | switch | off; heuristics enabled | Disable ligand-based evaluation heuristics. |
| `--adgpu-no-autostop` | switch | off; autostop enabled | Disable convergence-based early stopping. |
| `--adgpu-local-search` | `sw`, `sd`, `fire`, `ad`, `adam` | `ad` | Select the AutoDock-GPU local-search method. |
| `--adgpu-cpu-threads` | positive integer | `4` | CPU threads used by each overlapped AutoDock-GPU file-list process. |
| `--adgpu-workers` | `auto` or positive integer | `auto` | Concurrent same-GPU processes. Values above one use a managed CUDA MPS service. |
| `--adgpu-executable` | command or executable path | `autodock_gpu` | Override the selected AutoDock-GPU binary, for example a work-item-specific build. |

### Preparation, batching, validation, and output

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--batch-size` | `auto` or positive integer | `auto` | Outer docking batch size selected from workload and hardware. |
| `--batch-profile` | JSON path | unset | Reuse a compatible measured docking batch/worker profile. |
| `--prep-workers` | `auto` or positive integer | `auto` | Parallel RDKit/Meeko ligand-preparation workers. Auto respects physical cores, affinity, and RAM. |
| `--prep-mode` | `standard`, `fast` | `standard` | Standard includes separate force-field minimization; fast skips it. |
| `--embed-max-attempts` | `auto` or positive integer | `auto` | Bound ETKDG attempts per molecule. Auto uses the portable hard-molecule policy. |
| `--embed-timeout` | `auto` or positive integer seconds | `auto` | Time guard for each ETKDG phase. Auto prevents hard molecules from stalling the batch. |
| `--validation-workers` | `auto` or positive integer | `auto` | Parallel RDKit validation workers. |
| `--fragment-policy` | `reject`, `largest` | `reject` | Reject multi-fragment SMILES or keep only their largest fragment. |
| `--no-deduplicate` | switch | off; deduplication enabled | Preserve repeated canonical molecular identities. |
| `--docking-gpus` | `auto` or positive integer | `auto` | Number of visible GPUs used for physical docking. Auto uses all visible GPUs. |
| `--scratch-dir` | directory path | system/job temporary area | Override temporary ligand and engine workspace. |
| `--keep-work` | switch | off | Preserve temporary prepared ligands and engine files. |
| `--pose-output` | `none`, `merged`, `individual` | `merged` for `dock`; `none` for `fit`/`run` | Save scores only, one merged pose stream, or one pose file per ligand. |
| `--individual-poses` | switch | off | Compatibility alias for `--pose-output individual`. |

### Sharding controls

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--docking-logical-shards` | positive integer | `4` | Fixed reproducibility shards for `fit`/`run`, scheduled over the selected physical GPUs. Keep four for release-equivalent fitting. |
| `--device-id` | integer >= 0 | `0` | Visible CUDA device used by a manually sharded `dock` invocation. |
| `--num-shards` | positive integer | `1` | Divide regular docking into this many deterministic manual shards. A non-default manual shard plan disables automatic multi-GPU fan-out. |
| `--shard-index` | integer in `[0, num-shards)` | `0` | Zero-based regular-docking shard to execute. |

For the fitting workflow, release-equivalent labels use Uni-Dock/Vina,
`fast`, seed `181129`, one mode, refinement enabled, 5 A padding, fragment
rejection, deduplication, and four logical shards. Any deliberate change is
recorded as a custom protocol.

## Target fitting and active learning

`fit` prepares and fits a reusable target without a final screen. `run`
performs the same fit and then executes the requested final screen.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--al-rounds` | integer `0` through `5` | `0` | Number of released active-learning rounds; zero fits only the initial target head. Available on `fit` and `run`. |

Both commands also accept the runtime, target, and docking sections above.
Fitting a new target requires the optional UDRL/active-learning release asset
bundle; check it with `doctor --require-fit-assets`.

## Screening and gMolAI encoding

These options apply to `screen` and `run`. The generated maximum-speed path
keeps one iGen3 worker and one gMolAI/head worker resident per selected GPU and
enables cross-batch overlap automatically.

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--screen-name` | filename-safe text | `final` | Name of the reusable screen below the fitted job. |
| `--stream-batch-size` | `auto` or positive integer | `auto` | Molecules per durable validate/encode/score stream block. Auto considers GPU count, VRAM, RAM, scratch, and workload. |
| `--max-stream-batches` | positive integer | automatic safety cap | Stop after this many replenishment blocks if the requested finite-score count cannot be filled. |
| `--exclude-reference-libraries` | switch | off | Exclude exact identities present in fixed UDRL, AL, and test libraries. |
| `--save-policy` | `all`, `threshold` | `all` | Save every finite score or only scores meeting a threshold. |
| `--score-threshold` | float from `0` to `1` | unset | Minimum ensemble score to retain. Supplying it implies `--save-policy threshold`. |
| `--save-embeddings`, `--keep-embeddings` | switch | off | Persist gMolAI NPZ embeddings instead of using only the faster in-memory score path. The two spellings are aliases. |
| `--encoder-backend` | `optimized`, `reference`, `verify` | `optimized` | Use the fast released encoder, the slower reference path, or verify optimized output against reference. |
| `--encoder-batch-size` | `auto` or positive integer | `auto` | gMolAI graph batch. Auto benchmarks qualified sizes and caches the fastest compatible choice. |
| `--encoder-node-budget` | positive integer | `16384` | Maximum aggregate graph-node budget for an encoder batch. |
| `--encoder-workers` | `auto` or positive integer | `auto` | RDKit graph-preparation workers, respecting affinity and available CPUs. |
| `--encoder-verify-rows` | positive integer | `1024` | Maximum rows compared with the reference encoder when backend `verify` is selected. |
| `--encoder-threads` | positive integer | `4` | PyTorch CPU thread count inside each encoder worker. |
| `--encoder-device` | `auto`, `cpu`, `cuda`, or `cuda:N` | `auto` | Override the gMolAI Torch device. Normal GPU screens should keep auto. |
| `--screen-gpus` | `auto` or positive integer | `auto` | Number of visible GPUs used for generation, encoding, and target-head inference. Auto uses all visible GPUs. |
| `--generation-logical-shards` | `auto` or positive integer | `auto` | Deterministic generation shards per stream block. Auto matches `--screen-gpus`; fix it for controlled cross-hardware benchmarks. |
| `--validation-workers` | `auto` or positive integer | `auto` | RDKit validation workers for `screen`; `run` shares the identically named docking/input setting. |
| `--fragment-policy` | `reject`, `largest` | `reject` | Multi-fragment handling for `screen`; `run` shares the identically named docking/input setting. |

`--save-policy threshold` requires `--score-threshold`. Scores are target-head
classifier outputs, not docking energies or calibrated binding probabilities.
Exact canonical-SMILES deduplication remains enabled for ultra screening.

## Count-only maximum-speed screening

```text
./igenvs-ultra screen-fast MOLECULES
```

| Argument | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `MOLECULES` | positive integer | required | Exact number of successfully encoded, finite scores to commit. |

Run the command inside a completed fit/run job, or set `IGENVS_ULTRA_JOB` to
that job. It expands to a generated `screen` using the normal automatic
defaults and the screen name `fast-MOLECULES`. There are intentionally no
performance flags on this command.

## Diagnostics and status

### `doctor`

`doctor` accepts all runtime options plus:

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--no-gpu` | switch | off | Check files and tools without requiring a visible CUDA GPU. |
| `--require-fit-assets` | switch | off | Fail unless the optional multi-GB UDRL/active-learning fitting bundle is present. |

### `status`

| Flag | Accepted value | Default | Description |
| --- | --- | --- | --- |
| `--job-dir` | directory path | required | Fit/run job whose completed and pending stages should be printed. |

## Command requirements at a glance

| Command | Required input |
| --- | --- |
| `doctor` | none |
| `dock` | one target source, one molecule source, and `--output-dir` |
| `fit` | one target source and `--output-dir` |
| `screen` | `--job-dir` and one molecule source |
| `screen-fast` | positive positional molecule count; completed job discovered from the working directory or environment |
| `run` | one target source, one final molecule source, and `--output-dir` |
| `status` | `--job-dir` |

## Useful environment variables

These are not CLI flags, but they provide convenient defaults:

| Variable | Purpose |
| --- | --- |
| `IGENVS_ULTRA_ASSETS` | Project/release-assets root. The repository launcher sets this automatically. |
| `IGENVS_DOCKER_IMAGE` | Default iGenVS Docker image name or digest. |
| `GMOLAI_DOCKER_IMAGE` | Default gMolAI Docker image name or digest. |
| `IGENVS_IMAGE` | Default iGenVS Apptainer SIF path. |
| `GMOLAI_IMAGE` | Default gMolAI Apptainer SIF path. |
| `IGENVS_ULTRA_JOB` | Completed target job used by `screen-fast`. |
| `IGENVS_ULTRA_PROFILE_CACHE` | Override the portable hardware-profile cache directory. |
| `CUDA_VISIBLE_DEVICES` | GPU visibility used when `--gpu-ids` is omitted. |

Explicit CLI options take precedence over their environment-variable
counterparts.
